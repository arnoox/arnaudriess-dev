The problem

A generated binding can compile and still be wrong.

bindgen and cbindgen do the mechanical translation well. The errors occur where Rust and C make different assumptions. No compiler compares these assumptions.

{{ }}Binding gate

The checks run in CI.

Each audit or build includes a binding gate for the pipeline. When the team generates the binding again, the gate shows if it is still correct.

  • Pinned bindgen or cbindgen version and configuration
  • Layout and ABI checks against the real C build
  • Rules that flag changes to callbacks, ownership, and unsafe code
  • Half-day handover. The team learns the reason for each check.

What the evidence covers

Scope of the evidence.

I show two things. No safe Rust caller can cause undefined behavior through the binding. No C contract is broken without a report. The behavior of the library is not in scope.

{{ }}In scope

  • The generated layer: pinned generator, configuration, layout and ABI
  • The unsafe wrapper: null, lifetimes, ownership, callbacks, panics, threads, error codes
  • The safe signatures that expose it
  • Both directions: bindgen (Rust calls C) and cbindgen (C calls Rust)

{{ }}Out of scope

  • Internals and functional correctness of the C or Rust library
  • The meaning of values, such as units and ranges, unless a wrong value causes undefined behavior
  • An idiomatic Rust API on top, as long as it has no unsafe
  • Toolchain qualification, beyond the ABI checks on the target
  • The safety argument. The report is an input to it.

FAQ

Questions.

What is a surface point?

Every function that crosses the boundary between Rust and C counts one point. Things where Rust and C can disagree count more: callbacks, ownership that moves across, threads, unions, and functions whose contract is unclear.

How do I know my size before I pay?

Not necessary. The assessment counts the points and gives the size and the fixed price.

What if my binding grows during the audit?

The price is fixed for the scope of the assessment. If the scope grows, I first give a fixed price for the added code.

Do you need our whole source code?

No. For the assessment, the crate is enough, or the headers plus the list of functions in use.

Does this work when C calls Rust?

Yes. For cbindgen, the risk is in the export shims: panics, null pointers, memory ownership, and the calling thread. C callers get the contract written into the header.

Our C headers are poorly documented. Is that a problem?

No. I send one list of questions with a deadline. If a question has no answer, I assume the safe case and write it in the report. A missing contract is a finding.

Can you audit a binding you built yourself?

Build and audit are separate work packages. My own code must pass the same checks. If the integrity level needs an independent review, we agree on a second reviewer before the work starts.

What if my team fixes the findings?

The report is yours, and your team can fix the findings. With the subscription, I re-check the fixes, up to two rounds included.

When does the subscription start?

With the audit report, so that I can re-check the fixes right away. Cancel at any time.
